# Captured pool semantic correction V2

This explicit consumer supplements, and does not edit or retarget, the protected
V1 driver, collector, native freshness verifier, original objectives or receipts.
The refused original output phase remains refused. No equivalent SQL job is
created or replayed by this offline consumer.

Two source-backed semantic assumptions are corrected: an active campus reference
uses `GLOBAL` with no parent campus, while its campaign uses `CAMPUS`; Prisma
per-statement timestamp defaults need not be identical inside one transaction.
Both creation timestamps must remain in the independently collected window, audit
must follow version creation, and their difference must not exceed that window's
already supplied clock-skew bound (at most 1,000 ms). No raw value is rewritten.
An isolated actual Prisma 6.19.3 / RC48 / PostgreSQL17 transaction demonstrated
distinct defaults 39 ms apart with identical transaction ID and transaction time.
That LOCAL experiment is not production authentication or a historical timestamp.

The captured consumer requires the failed phase's fixed metadata, six terminal
journal events, unique execution/UID, task0/attempt0/private network, immutable
runtime bundle, bounded original native read timestamps, source-bound ciphertext
and exact independently pinned actor/intent/window bytes. All metadata checks
precede the explicit local key callback. Production use additionally requires the
qualified host to authenticate immutable receipt/checkpoint hashes and protected
source before granting that capability; typed JSON alone cannot establish origin.

Freshness is reported only at the actual recorded capture time. No past clock is
supplied to a native verifier, no current freshness or provider cryptographic
signature is invented, and the original phase is not relabelled SUCCESS. The
corrected proof retains all original intent, actor, capacity, scope, audit, cursor,
counter and complete raw PRE/POST preservation checks and historical-hash reserve.
The new status names contract V2 explicitly. Native acceptance, full production
preservation and activation remain false.

Synthetic fixtures/tests use generated RSA material only. Local qualification and
CI do not authorize access to production private material or imply a deployment.
The separate runtime-image draft, incomplete authority/CLI, permission lineage
reserve, backup/recoverability and actual Sheets activation remain separate gates.
