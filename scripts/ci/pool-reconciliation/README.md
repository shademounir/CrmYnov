# Controlled pool reconciliation — semantic proposal only

This pure module prepares the separately requested reconciliation contract. It
does not reconstruct the historical raw SQL hash, authenticate native evidence,
accept the current pool as a baseline, or authorize execution or activation.
Source review or merge does not change those limitations.

The fixed-intent wrapper requires the complete private original intent bytes,
identified only by their digest here. No contact data or private original receipt
is committed. The exported semantic validator exists for wholly synthetic tests;
it is not an operational entry point and always returns native acceptance and
activation authorization as false. No default catalog, runtime integration,
credentials, SQL client, provider calls, or job creation is included.

## Preserved constraints

- The original ordered GLOBAL/CAMPAIGN rules and four ordered capacities remain.
- Creation actor identity must be independently pinned, not learned from a new
  audit row. The bounded historical window must be separately reviewed against
  the pinned backup/DOM receipt digests; it is not an exact submission timestamp.
- One configuration/version/creation audit must agree with the full stored rules.
  Rule IDs and previously uncaptured technical timestamps are constrained and
  preserved in a fresh PRE/POST comparison, not retroactively authenticated.
- Prospective counters can grow and gain valid keys; they must not disappear or
  decrease. Saved normalization fields are not current workload or counter zero.
- POST requires a distinct single-use job/execution and matching helper, image
  and database binding. The module validates claims, not their native origin.

## Operational work still required

Independent actor/window authority, a protected official native-output verifier,
new purpose-specific guards/driver/objective/catalog and actual bounded READ ONLY
observations remain absent. Existing RC47 driver/sampler guards are unchanged and
must not be retargeted to run this proposal.

The runtime migration-ledger access gap is not omitted or repaired. Any separate
schema-only observation under an existing identity needs its own reviewed contract
and authority. Two separate transactions do not prove one shared database snapshot.

N0=2586, its generation, resume2587+, the 547 dispositions, mail and every other
preservation/activation requirement remain separate. No new cohort, resave, seed,
migration, privilege grant, deployment, or native acceptance is performed here.

The original six-file private draft remains immutable outside the repository.
This proposed source extracts its validation stages for review and additionally
rejects table-shaped objects that are not arrays. Tests use synthetic IDs, rules,
audit rows and native-source claims; no real snapshot or private intent is loaded.
